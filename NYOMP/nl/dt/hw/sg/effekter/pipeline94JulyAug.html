Intruducing Open Inventor

July/August 1994 Issue of Pipeline

Open Inventor 2.0 is the second major release of the
Inventor 3D Toolkit, previously called IRIS Inventor 1.0.
Open Inventor is an object-oriented 3D toolkit (based on
C++ with a C Application Programming Interface (API)), that
offers a comprehensive solution to traditional 3D
programming problems. Open Inventor allows users to focus
on the applications solution rather than graphics hardware
implementation. It presents a programming model based on a
3D scene database which includes a rich set of objects such
as cubes, polygons, materials, cameras, lights, trackballs,
engines, 3D viewers, and editors that shorten the
development cycle and extend 3D programming capabilities.
In addition, it provides an event model that simplifies 3D
interaction.

Programming in Open Inventor 2.0 simplifies the
implementation of 3D graphics features such as: true
geometric picking, 3D locate highlighting, animation,
physical constraints, object naming, level-of-detail,
object culling, interactive direct manipulation of scene
objects, bounding box calculations, selection, automatic
render caching, reusable viewers, instancing, and
cut-and-paste.

Because of its object-oriented architecture, Open Inventor
encourages users to extend and customize the toolkit
through subclassing in C++.

This article provides an overview of Open Inventor 2.0 as
well as a discussion of its major features and performance
enhancements over IRIS Inventor 1.0. Interested users are
encouraged to refer to the section titled "For More
Information" at the end of this article.

IRIS Inventor and Open Inventor


Open Inventor 2.0 presents three major advances over 
IRIS Inventor: 

o      major performance increases 
o      many new features 
o      openness 

The performance increases are significant and are due to a
combination of re-writing and tuning the entire GL
rendering framework plus several system enhancements.  Open
Inventor also includes many new objects, tools, and
features that were requested by IRIS Inventor 1.0 users.
Lastly, the Open in Open Inventor refers to the fact that
the toolkit uses OpenGL for all rendering and is portable
to non-SGI platforms. For more information, refer to
Chapter 3 of the Open Inventor Release Notes.

Performance Enhancements in Open Inventor 2.0


In designing and implementing Open Inventor 2.0, the first
priority was to deliver increased performance. The
internals of Open Inventor underwent a major re-write with
a singular focus on speed. From the bottom (3D database) up
(Nodekits, Manipulators, and Viewers), many objects were
optimized and grouped for efficiency while many of the
inefficient objects were eliminated altogether. This
section will list some of the major changes. For a complete
list, refer to Chapter 3 of the Open Inventor Release
Notes.

Efficient use of OpenGL


Open Inventor is able to achieve a performance level that
is as fast or faster than typical OpenGL programs. Even
though Open Inventor is architecturally a layer above
OpenGL, its efficient use of OpenGL resources and other
performance oriented features allow Open Inventor
applications to perform at speeds faster than typical
OpenGL applications.

Automatic Render Caching


Open Inventor 2.0 contains a new feature that results in
fast OpenGL rendering. This is done by automatically
building OpenGL display lists for the parts of the scene
database that do not change. In most cases, this results in
straight OpenGL rendering and no database traversal
overhead.

In IRIS Inventor, caching was either on or off. Open
Inventor 2.0 supports a third setting, auto. This
significantly improves performance and simplifies
programming.

Object Culling


Open Inventor 2.0 contains a performance oriented feature
called object culling. During rendering, objects which are
outside the field of view will be skipped (culled). As a
result, the system does not waste time and resources
rendering objects that are not within the view volume.

Level-of-Detail Objects


Open Inventor 2.0 introduces a new object,
SoLevelOfDetail(3), which allows programmers and users to
specify a sequence of representations for an object. This
sequence is a list of objects ordered by decreasing
rendering detail. The Level-of-Detail object automatically
chooses the appropriate representation based on the view.
This can result in significant performance increases
without noticeable changes in the image.  See the Open
Inventor slotcar game (available on the Inventor Games
CD-ROM) for a good example of Level-of-Detail.

Scene Graph Optimization


Open Inventor 2.0 introduces a new program, ivquicken(1),
that reads an Inventor file and attempts to optimize it
through scene graph restructuring for better rendering
speed. Changes to the scene graph include:

o      Explicit transformation of coordinates and normals 
o      Removal of hierarchical transforms whenever possible 
o      Conversion of face sets and indexed face sets into 
       indexed triangle strip sets 
o      Generation of explicit normals for objects with 
       undefined normals 
o      Removal of SoFile(3) nodes

Other Performance Enhancements


There is insufficient room in this article to list all of
the performance enhancements that have been made to Open
Inventor. In general, every attempt has been made to
increase the efficiency of all Open Inventor objects. In
addition, a variety of measures have been taken to reduce
unnecessary memory usage.

New Features in Open Inventor 2.0


In addition to performance enhancements, Open Inventor also
has many new features to assist the programmer. For more
information on these and other features, refer to Chapter 3
of the Open Inventor Release Notes.

Naming
       Nodes, paths, and engines can have names (strings)
       associated with them. This allows for easy identification
       of objects when searching through the scene database for
       them. Like most objects in Inventor, names can either be
       specified programmatically or in the Inventor file format
       where no recompilation of code is necessary.

Get Primitives and the Callback Action 
       A new feature has been added to the generic
       Inventor traversal action SoCallbackAction(3), that
       allows for shapes to return primitives (triangles,
       lines, points, normals, texturecoords, etc.)
       describing the object.  For an example, refer to
       the  program vortex in the directory
       /usr/share/src/Inventor/samples/vortex (available
       on the Open Inventor CD-ROM).

Printing
       Printing has been completely re-implemented using
       OpenGL rendering to an off-screen image. All
       rendering features can now be printed (e.g.,
       textures and transparency). The new class,
       SoOffscreenRenderer(3), renders a scene to an
       offscreen X pixmap and returns either a Postscript
       bitmap image or an unsigned character buffer.

Texture Image Field 
       The SoTexture2(3) object now has a field which
       specifies an in-memory texture array.  Users can
       specify the texture as either a file or an array.

Overlay Planes Support 
       This release fully supports overlay plane rendering
       in SoXtRenderArea(3) and Viewers. Users can now
       make menu selections or render in the overlay
       planes without causing re-draw events and time
       consuming re-renderings of complicated scenes in
       the normal planes.

Stereo         
       The Viewers now support stereo. (For a
       demonstration, run SceneViewer(1) or ivview(1) and
       select stereo viewing under the Preferences menu.)

3D Text 
       SoText3(3) now supports complexity and default 
       texturing, and is much faster.

ivview
       Ivview(1) is a new lightweight performance-oriented
       viewer for Inventor models. As a default, ivview
       runs ivquicken(1) on the input file to optimize the
       scene graph for faster traversal. Ivview also
       contains a performance meter. Refer to the manual
       pages for ivview(1) and ivquicken(1) for more
       information.

gview  
       Gview(1) is a new demo program that allows users to
       graphically view and edit their scene graphs.

File Reading Improvements 
       If an unrecognized object is found in an Inventor
       file, the reader will automatically search for the
       appropriate Dynamic Shared Object (DSO) and link it
       in at run-time. This ensures that user-defined
       classes can be read by any Inventor program.
       Furthermore, Open Inventor 2.0 also includes a
       feature that allows alternate representations of
       user-defined objects. This allows users to create
       surrogate representations of objects for
       cross-application data sharing.

Engines for Animation and Constraints 
       Engine nodes are new classes that can provide
       animation and constraints to Inventor scene graphs
       (for example, rotor, pendulum, shuttle, and
       blinker). Engines are incorporated into the scene
       graph to cause animated movement or other complex
       behavior. Engines can be connected together to form
       more complex and interesting behaviors. Note that
       engines are written out to the Inventor files where
       subsequent fine-tuning of animation or constraint
       parameters can be done without recompiling code.
       Refer to the manual page for SoEngine(3) for more
       information.

Manipulator and Draggers
       Manipulators are now derived from NodeKits. They
       have been re-written and simplified for better
       performance. Furthermore, a new class of objects
       called Draggers have been introduced. Note that
       Manipulators and Draggers can be written to
       Inventor files.

Error Handling
       Inventor now supports a formal error handling
       system. Note that the API was not affected by this
       change. All Inventor error messages are now posted
       to an SoError(3) class. The application can supply
       its own error handlers, making it possible to route
       error messages to dialogs, as well as stderr or
       stdout. When debugging, it is possible to set a
       breakpoint to stop right before an error is
       handled. Refer to the manual page for SoError(3) or
       The Inventor Mentor: Programming Object-Oriented 3D
       Graphics with Open Inventor (available on-line with
       InSight(1)) for details.

Simplified Makefiles 
       Open Inventor 2.0 Makefiles have been simplified.
       Refer to /usr/share/src/Inventor/samples/*/Makefile
       for examples of the new simplified Makefiles. Note
       that dependent libraries are implied and thus are
       no longer needed in the link line (e.g., libGL).

Samples and Demos 
       There are a variety of new sample and demo programs
       available with this new release. Binaries of these
       demos are available in /usr/demos/Inventor, (in
       inventor_eoe from the IRIX 5.2 CD-ROM), while the
       source is available in /usr/share/src/Inventor (in
       inventor_dev from the Open Inventor CD-ROM).

The Inventor Debug Library


The Inventor debug library contains a variety of run-time
error checking routines that detect programmer error. It is
recommended that this library be used for all developmental
work. To run programs with the debug library, be sure that
the subsystem inventor_dev.sw.debug is installed. Before
running the program in the Cshell, type:

% setenv LD_LIBRARY_PATH /usr/lib/InventorDebug

for the Bourne shell, type:

$ LD_LIBRARY_PATH=/usr/lib/InventorDebug 

$ export LD_LIBRARY_PATH

To turn off debugging in the Cshell, type

% unsetenv LD_LIBRARY_PATH

in the Bourne shell, type:

$ unset LD_LIBRARY_PATH

Remember that it is not necessary to re-link programs to
run with debugging turned on. This feature can save large
amounts of time in debugging and error checking.

Compatibility


Some of the changes that have been made between IRIS
Inventor 1.0 and Open Inventor 2.0 have resulted in
compatibility issues. This section will briefly discuss
these problems. For more information, refer to Chapter 4 of
the Open Inventor Release Notes.

API Changes


Open Inventor 2.0 has changed some of the API and may
require source code modification of 1.0 Inventor programs.
Typically, the modifications are only minor syntactical
changes, but in some cases the changes can be significant.
For example, if programs use derived classes from Inventor
objects and use IRIS GL for rendering, then that section of
the program must be rewritten using OpenGL.

Inventor File Format


Inventor provides a standardized 3D file format for easy
model interchange between applications. Objects and scenes
that are saved to a file retain their full 3D physical
characteristics and can be read into another program. This
feature is used by many SGI applications in sharing 3D
models. One of the main advantages of using the Inventor
file format is the speed in making changes to a scene or
model without recompiling code. Also, because engines are
written to a file, animations can be implemented and fine
tuned without writing any C or C++ code.

In Open Inventor 2.0, the Inventor file format has
undergone minor syntactic changes from IRIS Inventor 1.0.
When reading IRIS Inventor 1.0 files under Open Inventor
2.0, Open Inventor will do its best to resolve
discrepancies and may report warning messages. When
converting from Open Inventor 2.0 to IRIS Inventor 1.0, use
the program iv2toiv1(1) to convert the file format.

Installation Issues


Open Inventor 2.0 Dynamic Shared Object (DSO) libraries are
not compatible with IRIS Inventor 1.x applications.
Compatibility subsystems containing the correct libraries
have been provided to ensure that programs linked with
Inventor 1.0.1 or 1.1.2 will still run. If users will be
executing binaries from previous releases of Inventor, be
sure that the following subsystems are installed (from the
IRIX 5.2 CD-ROM):

inventor_eoe.sw.1_0
inventor_eoe.sw.1_1

When installing Open Inventor 2.0 on a system running IRIX
5.2, there are some issues to consider depending on the
platform and whether the programmer wishes to continue
development with IRIS Inventor. The following are three
typical scenarios.

Scenario 1


If the system is a Personal IRIS without Elan graphics, or
the system has VGX(T) or GT(X) graphics, Open Inventor
cannot be installed because currently there is no support
for OpenGL on these platforms. IRIS Inventor 1.1.2 must be
used instead.

Scenario 2


If the system is an Indy, Indigo, Indigo2, Crimson, or Onyx
running IRIX 5.2, load the Open Inventor 2.0 CD-ROM using
the inst(1M) instructions.

Scenario 3


If the system will be used for simultaneous development
under both IRIS Inventor 1.1.2 and Open Inventor 2.0,
complete the following steps (note that the instructions in
the Open Inventor Release Notes are incorrect):

1.      Load Open Inventor 2.0 from the Open Inventor
       CD-ROM. This will remove all previous versions of
       the Inventor development software.

2.      Check to make sure that the IRIS Inventor 1.1.2
       execution environment is there:

       % versions -v inventor_eoe.sw.1_1

       If nothing is returned, install the software from
       the IRIX 5.2 CD-ROM.

3.      Create a directory to hold IRIS Inventor 1.1.2
       developer software.

       # mkdir /usr/myroot

       Make inst think that the prerequisites are
       installed

       # mkdir -p /usr/myroot/var/inst 

       # cp /var/inst/{c,dev,c_dev,gl_dev,\
       motif_eoe,inventor_eoe} /usr/myroot/var/inst

4.     Install Inventor 1.1.2 under the alternate root 
       directory

       # inst -r /usr/myroot -f inventor_dev

5.     To make Inventor 1.1.2 examples in this new 
       directory:

       # cd /usr/myroot/usr/share/src/Inventor/examples/PG1

6.     Modify the Makefile to include the appropriate 
       directories. Change this:

       #------------------------------------------
       include /usr/include/make/commondefs
       # C++ source files:

       to this:

       #------------------------------------------
       include /usr/include/make/commondefs
       LC++INCS = -I/usr/myroot/usr/include 
       LCINCS = -I/usr/myroot/usr/include 
       LLDOPTS = -L/usr/myroot/usr/lib
       # C++ source files:

7.     To run Inventor 1.1.2 programs:

       # ln -s /usr/lib/libInventor.so.1 /usr/myroot/usr/lib/libInventor.so
